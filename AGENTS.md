# Правила для агента (стол + UI)

## Оверлеи на столе (DOM поверх канваса)

Элементы, которые визуально «лежат на поле» (слепая зона богов и аналогичные виджеты), должны вести себя как отрисовка на канвасе при **зуме камеры**:

- Размеры и позиции в **экранных пикселях** считать из мира через `boardWorldToScreen` / ту же модель, что и рендер.
- **Рамки, отступы и зазоры** между частями виджета задавать как `(базовое_значение_при_zoom_1) * camera.zoom` (или эквивалент через уже масштабируемые величины), а не фиксированные `px` в CSS, если нужно совпадение с юнитами, ландшафтом и т.д.
- Не полагаться на одну статическую толщину `border` в CSS для таких блоков, если зум меняется.

Исключения: чисто экранный UI (панель армии, меню), который не привязан к масштабу поля.

## Превью в браузере (`vite preview`)

`vite preview` раздаёт **собранный** `dist/`; правки в `src/` без пересборки в превью **не видны**.

**Обязанность агента:** если пользователь просит **перезапустить превью**, **запустить превью**, **превью с WebSocket**, **мультиплеер-превью**, **preview:mp** или любой эквивалент — агент **сам** выполняет нужные команды в терминале (остановка процессов на портах, `npm run build`, запуск). **Не** перекладывать это на пользователя инструкциями вида «запустите у себя».

Когда пользователь просит **перезапустить превью** (или обновить превью после изменений клиента), агент должен:

1. Остановить уже запущенный `vite preview`, если он держит порт **4173** (или соответствующий процесс).
2. Выполнить **`npm run build`** в корне репозитория.
3. Запустить **`npm run preview`** снова.

Когда нужен **превью вместе с сервером комнат (WebSocket)** — после шагов выше (или вместо шага 3) запускать **`npm run preview:mp`** из `package.json` (сборка + `roomServer` на **3333** + `vite preview --host` на **4173** с прокси `/__mp_ws`). Перед этим остановить конфликтующие процессы на **4173** и **3333**, если они уже заняты старым запуском.
