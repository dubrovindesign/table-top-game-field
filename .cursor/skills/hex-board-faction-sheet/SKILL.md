# Hex board — спрайтшит фракции → каталог

## Цель

По **лицевому** и **оборотному** листам с сеткой карточек собрать: нарезку в `public/catalog-units/<id>/`, юниты и хотспоты в `src/catalog/units/` и `hotspots/`, при необходимости лидера в `leaders.json`, пересобрать бандл. Серые кубы на карте в данных — поле **`black`**.

Канон доменов, фракций и имён — **[hex-board-canon](../hex-board-canon/SKILL.md)**; не вводить параллельные id доменов.

## 1. Входные файлы

- Два листа с сеткой карточек: **любые имена файлов**, как прислал пользователь (Steam, архив и т.д.).
- Оба листа — тот же **размер в пикселях** и та же **геометрия ячеек**.
- Иконка вкладки фракции: `public/<faction>.webp` — путь уже в `factions.json` (`panelIconSrc`).

**Кто есть лицо, а кто оборот — не по имени файла.** Агент **сам** смотрит оба изображения и решает: лицо = портреты, баннеры с именем, игровая «лицевая» вёрстка; оборот = текст правил, единый шаблон оборота. Дальше в скриптах использовать канонические пути (`public/...`) при необходимости **скопировав или положив** файлы под теми именами, которые уже прописаны в `split-*` / `build-*-scroll-cards`, — **без требования** к пользователю переименовывать исходники или держать в названии слова `front` / `back`.

## 2. Размер и сетка

1. Считать `width` × `height` через `sharp`/`metadata` (или аналог).
2. **Не** копировать сетку другой фракции без проверки: у Кригмарка было **6×4** (21 карта), у Кастилии **7×4** (25 карт, последний ряд — 4 ячейки).
3. Вывести ширину/высоту **одной ячейки**: `cellW = W / cols`, `cellH = H / 4` при 4 рядах (или иное число рядов, если лист другой).
4. Индекс → `(row, col)`: для неполного последнего ряда задать явное правило (пример Кастилии: индексы `0–20` — полная сетка `7` колонок; `21–24` — ряд `3`, колонки `0–3`).

Зафиксировать в новых скриптах ту же `cellRect`, что в **split** и **build-*-scroll-cards** (оборот режется теми же `left, top, width, height`).

## 3. Имена и стабильные id

- Порядок юнитов = порядок ячеек на лице (**слева направо, сверху вниз**).
- Отображаемое имя и титул — **как на карточке** (подпись баннера / полное имя с титулом).
- `id` в JSON: **ASCII slug**, один файл `src/catalog/units/<id>.json`; без переименований без нужды (сохранения/мультиплеер).

## 4. Статы и хотспоты

1. Нарезать лист на отдельные JPG по ячейкам (временная папка или скрипт) и **прочитать каждую карту** (или вручную по скану): ОЗ, защита (белый/зелёный), шаг/бег, размер, атаки, `hex`/`hexon`, маркеры веры при необходимости.
2. Заполнить **`scripts/generate-<faction>-catalog.mjs`**: массив юнитов с полями `card` и `regions`; геометрия зон — те же нормализованные доли, что в `generate-krigmark-catalog.mjs` (`A1`/`A2`/`SPLIT_*`), скрипт **scroll** потом пересчитает `y` под склейку.
3. Домен из `factions.json` для этой фракции (`destruction`, `death`, …). Ключевое слово на карточке — обычно одна строка в `keywords`.

## 5. Скрипты и порядок запуска

| Шаг | Действие |
|-----|----------|
| 1 | Добавить/править `scripts/split-<faction>-spritesheet.mjs` — путь к **лицевому** листу (после определения по содержимому §1), список `id` в порядке сетки, `cellRect`. |
| 2 | Добавить/править `scripts/generate-<faction>-catalog.mjs` — статы и регионы. |
| 3 | Добавить/править `scripts/build-<faction>-scroll-cards.mjs` — тот же список `id`, тот же `cellRect`, путь к **оборотному** листу. |
| 4 | В `package.json` — npm-скрипты вида `<faction>:split-sheet`, `<faction>:scroll-cards`. |
| 5 | Удалить старые `src/catalog/units/<faction>-*.json`, `hotspots`, `public/catalog-units/<faction>-*` при смене id. |
| 6 | `node scripts/generate-<faction>-catalog.mjs` → `npm run <faction>:split-sheet` → `npm run <faction>:scroll-cards`. |
| 7 | Обновить `src/catalog/leaders.json` (лидер + ростер). |
| 8 | `npm run catalog:bundle` (или полагаться на `npm run build`, если бандл встроен). |
| 9 | `npm run build` для проверки. |

Превью: по **AGENTS.md** после смены ассетов нужен **build** перед `vite preview`.

## 6. Карты богов и прочее

- **Карты богов**: массив `GOD_CARDS` в `src/godCards.ts`, поле `factionIds` — id из `factions.json`. Добавить спрайты/источники по тому же стилю, что существующие записи.
- Новая **фракция**: запись в `src/catalog/factions.json` + иконка в `public/`.
- Другие элементы (инвентарь, отдельные листы) — по аналогии с уже лежащими скриптами в `scripts/`, не смешивать с нарезкой юнитов без необходимости.

## 7. Чеклист агента

- [ ] Сетка и `cellRect` согласованы между split и scroll-back.
- [ ] Лицевой и оборотный лист не перепутаны (см. §1: по содержимому, не по имени файла).
- [ ] Имена и статы с **лицевых** карточек, не с шаблона другой фракции.
- [ ] Домены и id фракции по канону.
- [ ] Лидер и `roster` в `leaders.json`.
- [ ] Сборка и бандл каталога проходят.
