# Справка: арт к существующим юнитам

## Поля карточки, связанные с картинками

Источник типов: `UnitCardData` в `src/unitCard.ts`.

- **`sprite`** — основное изображение карточки в UI (часто длинная вертикальная картинка `image.jpg` = лицо + оборот).
- **`miniatureSprite`** — отдельный арт токена на поле; если нет, клиент может падать обратно на другие источники (см. комментарии в `unitCard.ts`).

В `public/catalog-units/<id>/` часто лежат:

- `face.jpg` — только лицо (удобно для превью и промежуточных шагов).
- `image.jpg` — то, что обычно в `sprite` и в `hotspots[].image`.
- `miniature.jpg` — миниатюра.

## Склейка лица и оборота

В репозитории уже есть паттерн: обрезка низа лица (`bottomCropPx` и т.д.), вертикальная склейка с полосой оборота, запись `scrollLayout: { faceH, totalH }` в хотспотах. Примеры:

- `scripts/build-castilla-scroll-cards.mjs`
- `scripts/build-mercenaries-kow-scroll-cards.mjs`
- `scripts/ingest-engeln-tornscape-pairs.mjs`
- `scripts/import-krig-standalone-cards.mjs`

Если **меняется только картинка** при тех же пропорциях — иногда достаточно заменить файлы без пересчёта регионов. Если меняется высота лица или оборота — пересчитать `scrollLayout` и масштаб `regions[].y`/`h` (в скриптах это делается через отношение `faceFullH / totalH`).

## Поиск юнита по имени

Быстрый обзор всех имён без открытия каждого файла:

```bash
# пример: извлечь пары id и name (jq), или grep по "name":
rg '"name":' src/catalog/units --glob '*.json'
```

Сопоставление делать с полем **`card.name`**, не с `id`, если пользователь ориентируется на текст с карты.

## Неоднозначности

- Одинаковые или почти одинаковые имена у разных фракций — сверять с контекстом пользователя (фракция, лидер, список юнитов в задаче).
- Варианты написания (кавычки, дефис, «ё/е») — нормализовать или показать пользователю варианты.
